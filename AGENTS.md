# Project Instructions

## Working context

- Use WSL as the terminal entry point for project commands and tools, including `bun`, `python`, and `docker`.
- Make changes directly in this project directory. Do not create or use a separate worktree unless the user asks for one.
- For coding, code review, and refactoring tasks, use the existing `ponytail`, `karpathy-guidelines` (Andrej Karpathy), and `sixwhyo` skills. Look for them in `.opencode/skills/`; if one is missing, search for and install/download it before proceeding.
- Before starting project work, find and follow the relevant planning or checklist `.md` file. If no suitable checklist exists, create or extend one before implementation.
- When a checklist-driven task is complete, update its `.md` checklist by checking off every item completed as part of the task.
